# /design — GAS アプリの場合の追加ルール

> SKILL.md の手順・モダンUIチェックリストはそのまま使う。ここに書いたことだけ、GAS 向けに読み替える。
> 役割分担も SKILL.md と同じ（ヒアリングは伴走役、`spec/design.md` の起草はデザイン担当）。伴走役は委譲文に「GAS アプリであること」と「下の GAS の画面の制約」を添える。

## 既存デザインの把握（手順 1 の読み替え）

- GAS アプリには `tailwind.config` がないことが多い。代わりに **`.html` ファイルの `<style>` と、使われている class 名**（CDN 版 Tailwind を読み込んでいる場合）を既存のデザインとして読む
- 画面ファイルが `Index.html` 1 枚にまとまっていることが多い。CSS・JS が同じファイルに入っている前提で読む

## GAS の画面で守ること（方針を書くときの制約）

GAS の画面（HtmlService）は Google の中の囲い（iframe）で表示される。方針がこの制約に合っているかを確認する：

- **外部の CSS・JS は https の CDN から読み込める**（Tailwind CDN、Google Fonts など）。http は読み込めない
- **スマホ表示の設定（viewport）は `.html` に書いても効かない**。`.gs` の `doGet` で `.addMetaTag('viewport', 'width=device-width, initial-scale=1')` を付ける
- **画面の切り替えは 1 枚の HTML の中で表示を切り替える** のが基本。別ページへ移る作りにする場合は URL パラメータ（`?view=...`）で分ける
- **リンクで外のサイトを開くときは `target="_top"` か `target="_blank"`** を付ける（付けないと囲いの中で開けず止まる）
- **画像ファイルは手軽に置けない**。アイコンはインライン SVG を使う（モダンUIチェックリストの「SVG アイコン」とも一致する）

## spec/design.md に書き足すこと

- 「GAS の画面の制約」として上の 5 点のうち、このアプリに関係するものを 1〜2 行で残す（後から機能を足すときの迷いを減らすため）

## 仕上がりの確認

- モダンUIチェックリストの確認は、**確認用 URL（/dev）をブラウザで開いて** 行う（`npm run dev` のようなローカル起動はない）
- スマホ幅の確認は、ブラウザの開発者ツールで画面幅を変えて見る
